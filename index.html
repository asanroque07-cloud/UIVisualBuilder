Data flow — DFD level 1

How a click, a saved character or a shared project moves through the app. Everything works locally first; the cloud path only runs when an account is signed in.

User / guestBrowser on any device
→
1.0 Dashboardindex.html · cloud.js
2.0 Character studiostudio.html · studio.js
3.0 Map studio & runtimegame.html · game.js
⇆
D1  localStoragedropform:projects · charlab:projects · mapstudio:maps
D2  Supabase Postgrespublic.projects · public.project_members
D3  Supabase Authauth.users (managed by Supabase)
  • 1.0 Dashboard reads and writes D1 dashboard designs, renders the project cards, and calls 4.0 for sign-in and sharing.
  • 2.0 Character studio reads and writes D1 characters, then exports a character as PNG, sprite sheet or JSON.
  • 3.0 Map studio & runtime reads characters from D1, builds and saves maps in D1, and runs the 2D / 3D play loop in the browser.
  • 4.0 Cloud sync (inside cloud.js) sends the signed-in user's projects to D2 through the Supabase REST API and authenticates against D3. Row-level security decides which rows a request may see.
  • Nothing is deleted on sign-out: local work stays in D1, cloud rows stay in D2. The schema in D2 is created once by running supabase/schema.sql.

Delete rules: deleting an account cascades to its projects and memberships; deleting a project cascades to its memberships. Indexes: projects_owner_idx, project_members_user_idx.

Row-level security is on for both tables. projects_read allows owners and members, projects_insert only the owner, projects_update owners and edit members, projects_delete only the owner. Members can read a membership row if it is theirs or if they own the project, and can remove themselves. SQL helpers: is_project_member(), can_edit_project(), share_project(), list_project_members().

Table creation

The tables are not created automatically. Run supabase/schema.sql once in Supabase → SQL Editor, then use the checks below to confirm the tables and functions exist.

Show the CREATE TABLE statements 
create table if not exists public.projects (
  id         text primary key,
  owner      uuid not null references auth.users (id) on delete cascade,
  name       text not null default 'Untitled',
  device     text not null default 'pc',
  data       jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

create table if not exists public.project_members (
  project_id text not null references public.projects (id) on delete cascade,
  user_id    uuid not null references auth.users (id) on delete cascade,
  role       text not null default 'edit' check (role in ('edit', 'view')),
  added_at   timestamptz not null default now(),
  primary key (project_id, user_id)
);

create index if not exists project_members_user_idx on public.project_members (user_id);
create index if not exists projects_owner_idx        on public.projects (owner);

alter table public.projects        enable row level security;
alter table public.project_members enable row level security;
